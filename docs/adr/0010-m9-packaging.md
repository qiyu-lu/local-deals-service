# ADR 0010：包装期的四个决定——仓库名、文档主干、笔记写法、以及不拆那一行

- 状态：**已决定**（2026-09-21）。仓库名停在 `local-deals-service`；主干文档收口为
  README + 索引 + ADR + 压测报告 + 运行手册；笔记与问答按「角色名 + 代码索引」写；
  **`tb_seckill_voucher` 热点行明确不拆**，作为已知边界保留。
- 关联：[M9 计划](../plan/m9-packaging-plan.md)、[V2 计划](../plan/v2-high-concurrency-plan.md)、
  [ADR 0007 决策 4](0007-m6-batch-fill.md)、[ADR 0009](0009-m8-multi-instance.md)、
  [压测报告](../benchmark-report.md)

## 背景

M0–M6、M8 之后，代码是对的、数字是齐的，但门面还停在教程状态：README 第一行写着教程名，
`docs/` 里躺着四篇描述 V1 的设计文档，而所有真正值钱的东西——三次故障演练、被证伪的两个预期、
测实了却没修的那条瓶颈——散在 ADR 和进度表里，面试前没法读。M9 只做包装，不动代码。

## 决策

### 1. 仓库名停在 `local-deals-service`，不改成计划里举例的 `local-deals-platform`

远端、`artifactId`、包名、镜像名已经一致，再改一次只是制造不一致。「平台」这个词放进定位语
（「本地生活商户券营销与交易平台——面向万级并发的秒杀、订单闭环与故障恢复」），不放进仓库名。
代价：仓库名里没有「平台」二字，靠 README 首句和 GitHub description 补。

### 2. 主干只留五类文档；V1 设计文档删而不改

主干 = README（首屏即结论）+ 文档索引 + 一里程碑一页的 ADR + 压测报告 + 运行手册，
合计控制在 2000 行以内。`docs/plan/`、`docs/notes/`、`docs/interview/` 不计入预算。

**V1 的四篇设计文档删掉，不重写**：秒杀那篇已被 ADR 0003–0006 取代，另外三篇的内容由笔记按当前
代码重写。改写等于维护两套说法，而两套里必然有一套是错的，读者没办法判断是哪套。tag `v2.0-m8`
里永久可查（`git show v2.0-m8:docs/design/<file>`）。同理 `docs/guides/environment-setup.md`
由 `docs/runbook.md` 取代而不是修补：旧 guide 混着「怎么操作」和「为什么」，运行手册只写前者。

### 3. 笔记用「角色名 + 代码索引」，问答用「答 / 展开 / 追问 / 别踩」

- **笔记**（`docs/notes/`，13 章）正文不出现类名、表名、Lua 文件名、配置项名，一律用角色名，
  章末给一张「角色名 → 真实名字」的代码索引。理由：面试时说的是机制不是标识符。每章有**详细流程**
  与**口述版**两份，口述版是用来背的，所以校对波单独跑了一遍——背错比没有更糟。
  代价：回查代码多一跳。
- **问答**（`docs/interview/`，114 题）按面试官的思路组织，允许少量真实类名，流程细节引用笔记而不重抄，
  **没做的先说没做再给业界方案与代价**，真实证据与假设方案分开写。
- 分工：笔记答「系统怎么工作」，问答答「你为什么这么做、出了事怎么办、数字哪来的」。

### 4. `tb_seckill_voucher` 那一行不拆

M8 把它从推断变成了实测：1/2/3 个实例的**提交次数/s 恒在 70–115，与实例数无关**，
三个实例烧掉三倍 CPU 只多落约 25% 的单，而 MySQL 只用了 0.24 核（共 4 核）。
这就是每批都要更新的同一行的代价，行锁不因为多了两个进程而变快。

**仍然不拆**，理由三条：

1. 三实例 3026 单/s 对目标场景（10 万人抢 1000 件）已经足够——那一轮的全链路对账是闭合的。
2. 拆法（按券分桶扣减 + 定期合并，或把库存移出 MySQL）会把**最后一道防线**从一条
   `stock >= n` 的条件更新变成一组需要自洽的数字。复制空窗演练刚刚证明这条防线是真正兜住
   超卖的那一层（Redis 最多多放 10.3%，MySQL 每轮恰好 30000 单、超卖恒 0），
   为了吞吐去动它，代价与收益不成比例。
3. 面试价值上，「测实了、知道怎么拆、算得出为什么现在不拆」比多一个分桶更值得讲。

回归条件写在 [V2 计划 M6](../plan/v2-high-concurrency-plan.md) 里，三条同时成立才重开：
到达速率远高于 2000/s、`drain_s_after_load` 重新大于 0、且 `persist_orders_per_s ÷ batch_mean`
不再随负载上升。**代价**：写路径的水平扩展上限就停在这里，加实例只加 CPU 不加吞吐；
这一条写进了 README 的已知边界、压测报告第 4 节和问答第 12 节，不藏。

## 代价与边界

- 主干文档收口后，V1 的过程记录只在 tag 里，靠 `git show` 才能读到。
- 笔记与问答是 2026-09-21 这个 commit 的快照；代码再改，它们不会自己跟上。
- 本次包装不含 GitHub description / topics 与本地目录改名，那三件由我手动做。
